Sample Spaces & Events

List what can happen before asking how likely it is.

Learning objective

Describe a random experiment with a sample space, and write an event as a subset of it.

Probability starts before any numbers appear. First you need a clear picture of what could happen. A random experiment is any process whose result you cannot predict for certain, even though you can list the possible results: tossing a coin, rolling a die, drawing a card, waiting for a bus.

The sample space, written Ω, is the set of every possible outcome. Think of it as the full menu. An outcome is one single item on that menu, and exactly one outcome happens each time the experiment is run.

An event is a yes-or-no question about the result, and we represent it by the set of outcomes that answer yes. “The die shows an even number” becomes {2, 4, 6}. So an event is just a subset of Ω, and we say the event happens when the actual outcome lies inside that subset.

Two events are special. The whole space Ω is the sure event, because something in it must happen. The empty set ∅ is the impossible event. Two events are mutually exclusive when they share no outcomes, so they can never both happen on the same run.

Choose outcomes at the finest level of detail you need. For two coin tosses, Ω = {HH, HT, TH, TT} has four outcomes, not three: “exactly one head” is an event made of two outcomes, HT and TH. Listing outcomes finely avoids many classic mistakes.

Definition (§1.1). A random experiment is a procedure whose result is not determined in advance but whose set of possible results is well defined. Each possible result is an outcome ω, and the set of all outcomes is the sample space Ω. The one rule: exactly one outcome occurs every time the experiment is run. So the outcomes must be mutually exclusive (two different outcomes cannot both happen) and collectively exhaustive (at least one of them must happen).
A gallery of sample spaces. One coin toss: {H, T}, finite with |Ω| = 2. Two dice, ordered: {1, …, 6}2, finite with |Ω| = 36. Toss until the first head: {1, 2, 3, …} ∪ {∞}, where ∞ means “never”, countably infinite. An infinite sequence of tosses: {0, 1}ℕ, uncountable. A spinner angle: [0, 2π), uncountable. Tomorrow’s closing price: (0, ∞), or a tick grid {0.01, 0.02, …}, a modelling choice. A whole price path on [0, T]: the continuous functions C[0, T], a function space.
Countable versus uncountable. A set is countable if it is finite or can be listed as a sequence x1, x2, x3, … (so ℕ, ℤ and ℚ are countable). It is uncountable otherwise: Cantor’s diagonal argument shows that [0, 1] and {0, 1}ℕ are uncountable, because the binary expansion 0.b1b2b3… identifies an infinite coin-toss sequence with a point of [0, 1]. This distinction decides whether probabilities can be assigned by adding up point masses (countable Ω) or need integration (uncountable Ω).
Choosing Ω is modelling, not truth. A sample space must be fine enough to express every question you will ask. For two dice, Ω = {same, different} is a legitimate sample space, but it cannot answer “is the sum 7?”. Rule of thumb: record the most detailed description you might need. You can always coarsen later by grouping outcomes into events, but you can never refine.
Quant lens. Whether a price is modelled on a tick grid (discrete Ω) or on (0, ∞) (continuous Ω) changes the mathematics. On a grid, “the price is exactly 100.00” has positive probability. On (0, ∞) it has probability 0, and one asks about intervals, hitting times and densities instead. Both are standard, and knowing which you are in is the first step of any model.
The governing relations
An event is a subset
A ⊆ Ω
Mutually exclusive events
A ∩ B = ∅
The one rule
exactly one outcome ω ∈ Ω occurs: outcomes are mutually exclusive and exhaustive
